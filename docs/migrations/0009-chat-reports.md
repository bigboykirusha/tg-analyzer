# 0009 — отчёт одним документом

Отчёт по чату теперь хранится одним JSON-документом в `chat_reports.report` вместо россыпи таблиц.

Что делает миграция:

- создаёт `chat_reports` и переносит в неё существующие отчёты из `chat_stats`/`daily_activity` (SQL-функции в `pg_temp` собирают документ версии 2);
- удаляет `chat_stats`, `global_stats`, `daily_activity` — их данные либо вошли в документ, либо приложением не читались;
- упрощает `parse_jobs` (одна задача — один чат: `chat_id`, `chat_name`, `error_message`) и убирает неиспользуемые колонки `telegram_sessions.dc_id`, `expires_at`.

Миграция необратима. Перед применением в production сделайте бэкап базы. После неё старая версия API не запустится, поэтому выкладывайте API и worker вместе с миграцией. Перенесённые отчёты открываются сразу; метрики, которых не было в старых таблицах (сессии, словарь собеседника и т. п.), появятся после повторного анализа чата.
