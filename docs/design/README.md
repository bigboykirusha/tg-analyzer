## Правила, которые проверяем на каждом экране

1. **Одна цифра — одно место.** Величину ниже по странице можно раскрыть, но не повторить. Отчёт и «Итоги» дают один ответ.
2. **Один вход в каждую вещь.** Аккаунт — внизу боковой панели на ПК и аватар в шапке на телефоне. Язык и тема — в аккаунте и в подвале сайта.
3. **Лайм — это собеседник.** Лайм — «их» сторона в данных и одна акцентная плитка на экран. Все кнопки графитовые.
4. **Без баннеров.** Сообщение стоит строкой рядом с тем, к чему относится.
5. **Primary одна на экран.** Иконки — только Lucide из `lib/icons.ts`, символы шрифта (✦ ↻ ⋯) вместо иконок не используем.

## Порядок работ

Каждый этап — отдельный коммит. После каждого: `pnpm lint && pnpm format:check && pnpm check`, `pnpm test:unit`, e2e, скриншоты 1440×900 и 390×844 в обеих темах (см. `CLAUDE.md`).

### Этап 0. Баги (первыми)

- [ ] **500 при обновлении страницы.** В проде F5 или прямая ссылка на `/dashboard` и `/chat/:id` даёт «Ошибка 500», переходы внутри приложения работают. Скорее всего, серверный рендер кабинета делает API-запрос без cookie пользователя. Решение: пробросить cookie в SSR-запросы (`useRequestHeaders(['cookie'])` / `$fetch` с заголовками) или отрендерить кабинет только на клиенте (`ssr: false` для `layouts/workspace.vue`-маршрутов через `routeRules`). Проверка: F5 на каждой странице кабинета под входом.
- [ ] **Тема на странице ошибки.** `error.vue` рисуется тёмной при выбранной светлой теме, а карточка со спектрограммой светлая на тёмном. Тема должна браться из cookie до первого кадра; карточка — на `--surface`.

## Что не трогаем

- Окно Mac и iPhone на лендинге, палитру «Чистый», Geist, Lucide.
- Аналитику в `packages/shared`: макеты меняют только вид и подачу.
- Структуру отчёта «Вы двое / Время / О чём» (в группе — «Люди / Общение / Время») и якорную навигацию.

## Если что-то не сходится

Макет рисовался на демо-данных, в коде бывают крайние случаи: один отчёт, группа без «ваших» сообщений, пустой месяц. Решение по крайнему случаю принимайте по правилам выше и опишите его в `docs/ROADMAP.md`.
