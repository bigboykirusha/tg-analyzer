# Промт: «Мелочи» — шкала отступов и размеров, сетка, вылизанность

Задача для Claude: свести систему к минимальному набору значений и выровнять по нему каждый экран. Цель — продукт, который выглядит как цельный премиальный, а не собранный из близких на глаз чисел.

---

Ты — дизайн-инженер. Твоя задача — убрать из «Портрета» лишние значения и выровнять по оставшимся каждый экран. Продуктовые решения, тексты и состав экранов не меняешь. Меняешь только отступы, размеры, сетку, выравнивание и ритм. Перед началом прочитай `CLAUDE.md`, `docs/design-system.md` и `docs/design/portrait-v3/README.md`. Отвечай владельцу по-русски.

## Источники

- **Код:** `apps/web/app/assets/styles/tokens.css` — единственный источник значений; компоненты лежат в `apps/web/app/components/**`.
- **Макеты:** генератор в `docs/design/portrait-v3/generator/` (`system.py` — CSS, `kit.py` — компоненты, `phone.py` и `desktop.py` — экраны).
- **Ориентиры:**
  - Apple HIG — layout, сетка в 8 pt, цели касания 44;
  - шкала space в Radix Themes;
  - 8dp в Material 3;
  - Primer.
  - Навыки: `impeccable` (polish, normalize), `apple-design`, `web-design-guidelines`.

## Этап 1. Опись: только факты, без мнений

Скриптом Playwright собери все значения, которые реально встречаются:

- на всех досках макетов (preview);
- на живом приложении в демо-режиме: 390 и 1440 px, светлая и тёмная тема, все экраны кабинета, отчёт, «Итоги», вход, публичные страницы.

Что собрать:

- **Пространство:** padding, margin и gap отдельно по каждому свойству.
- **Размеры:** высоты контролов, иконки, аватары, радиусы, толщины линий, тени, ширины колонок и панелей.
- **Типографика:** кегль, интерлиньяж, начертание, трекинг.
- **Цвета:** отдельно текст, фон и линии.

Для каждого значения укажи, сколько раз оно встречается, на каких экранах и в каких компонентах. Отдельным списком дай «подозрительные» места:

- значение встречается 1–3 раза;
- значение отличается от соседнего на 1–3 px;
- значение задано inline-стилем в генераторе или захардкожено в компоненте.

Итог этапа — таблица в `docs/design/portrait-v3/audits/07-inventory.md`: что есть, сколько разных значений по каждой категории.

## Этап 2. Минимальная шкала: у каждого шага своя роль

Предложи шкалу, в которой каждое значение отвечает на вопрос «для чего». Значения без роли удаляются. Стартовая гипотеза, которую нужно подтвердить или опровергнуть описью:

- **Пространство на основе 4.** Шаги: 4, 8, 12, 16, 24, 32, 48, 64, плюс 2 — только для волосяных зазоров. Роли:
  - внутри контрола;
  - между связанными элементами;
  - внутренний отступ карточки;
  - между карточками;
  - между разделами;
  - поля страницы.
- **Семантические токены поверх шкалы.** Например `--card-padding`, `--card-gap`, `--section-gap`, `--page-gutter`, `--stack-*`. Компоненты читают только семантику, сырые шаги — никогда.
- **Близость.** Отступ внутри группы всегда меньше, чем между группами, минимум в 1.5–2 раза. Шаги идут по иерархии: элемент → группа → карточка → раздел → страница.
- **Типографика:** не больше 8 ролей. Интерлиньяж на сетке 4. Трекинг только у display и заголовков. Три начертания.
- **Размеры:**
  - контролы — максимум три высоты;
  - иконки — 16 / 20 / 24;
  - аватары — максимум четыре;
  - радиусы концентричны: внутренний = внешний − отступ;
  - линия — одна толщина;
  - тени — максимум два уровня.
- **Сетка:**
  - поля страницы по ширинам;
  - максимальная ширина колонки;
  - ширина панели людей;
  - когда плитки идут в две колонки;
  - левые края всех блоков на одной вертикали;
  - вертикальный ритм кратен 4.

Для каждого удаляемого значения напиши, на что оно заменяется и где это заметно глазу. Каждое исключение обоснуй одной строкой в `docs/design-system.md`.

## Этап 3. Правила «премиальности», которые проверяются на каждом экране

1. **Одна анатомия карточки:** вопрос → ответ → картинка → сноска с одинаковыми зазорами везде.
2. **Ряд одной высоты.** Нижние края плиток в ряду совпадают, либо у разницы есть причина.
3. **Оптическое выравнивание.** Иконка и текст по центру строки, цифры табличные и выровнены по правому краю в колонках, у кнопки с иконкой оптический центр.
4. **Нет «почти»:** значений, отличающихся на 1–4 px от соседнего шага шкалы.
5. **Длина строки** — 45–75 знаков для чтения. Ни одно слово не висит одно на строке в заголовках и ответах.
6. **Пустота только намеренная.** Её размер — шаг шкалы, а не остаток.
7. **Цели касания** не меньше 44 на телефоне, карточка нажимается целиком.
8. **Одинаковые вещи выглядят одинаково на телефоне, планшете и ПК.** Меняются только поля, колонки и кегли по таблице ширин.

## Этап 4. Применить

- **Код.** Обнови `tokens.css` под шкалу и замени значения в компонентах. Ужесточи Stylelint (`stylelint-declaration-strict-value`): в компонентах для свойств пространства и размеров разрешены только токены.
- **Макеты.** Убери inline-стили пространства из генератора, всё через классы и токены `system.py`. Пересобери, опубликуй холст.
- **Проверку опиши в `apps/web/tests/e2e`** так, чтобы в будущем она падала на:
  - значение вне шкалы;
  - контраст ниже AA;
  - цель касания меньше 44;
  - горизонтальную прокрутку на 360–430 px.

## Этап 5. Проверить

- Повтори опись и составь таблицу «было N значений → стало M» по каждой категории.
- Сделай скриншоты до и после: 390 и 1440, светлая и тёмная тема.
- Один независимый агент смотрит только на скриншоты и чек-лист этапа 3 и отвечает «где выглядит не премиально и почему», с координатами.
- Исправь найденное. Второй круг проводи, только если первый нашёл больше пяти пунктов P1.
- Зелёными должны быть `pnpm lint`, `format:check`, `check`, `test:unit`, `test` и `test:e2e`.

## Организация

- **Агенты:**
  - опись — скрипт плюс один агент, который её сводит;
  - шкалу и правила решаешь сам;
  - применяешь сам по этапам;
  - один свежий агент проверяет результат.
- **Без лишнего.** Новых компонентов и экранов не добавлять. Решения владельца из `CLAUDE.md` не пересматривать без вопроса.
- **Когда спросить владельца.** Если удаление значения заметно меняет вид экрана — например другие поля страницы или кегль ответа, — спроси, показав две картинки «было / стало».
- **Сдача:**
  - короткий отчёт владельцу: сколько значений было и стало, что заметно изменилось, что осталось;
  - обновлённые `docs/design-system.md` и ROADMAP;
  - коммит и пуш.
