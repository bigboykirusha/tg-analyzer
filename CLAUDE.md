## Продукт

«Зеркало ваших переписок»: человек входит через Telegram, выбирает личный чат или группу и получает понятный отчёт. В отчёте баланс переписки, скорость ответов, ритм по часам и дням, частые слова и эмодзи, разговоры и динамика. Для групп добавляются роли участников, связи и общий словарь. «Итоги» — сторис в стиле Spotify Wrapped, которые можно сохранить картинкой 1080×1920 или отправить.

Главное обещание — приватность: тексты сообщений не сохраняются, в базе лежит только агрегированный отчёт. Отчёт удаляется из своего меню вместе со ссылками; «удалить всё» и «отключить Telegram» владелец не хочет. Фильтра мата нет нигде (решение 11.11).

Главный объект — отчёт по чату. Главная страница — «что я уже узнал»: плитки отчётов (у новичка — «С кого начнём?»). На телефоне плитки по две в ряд; имя, которое не помещается в строку половинной плитки, ставит плитку на всю ширину (`useTileRows`). Что ещё разобрать: на телефоне — край листа чатов внизу главной («Найти чат и разобрать», `HomeChatsPeek`; край тянется за пальцем, касание или подтягивание открывают лист на весь экран прямо из края, закрытый лист ложится обратно в край; в листе над списком — люди месяца), на ПК — лента «Разобрать ещё» под отчётами (круги людей месяца, первым — «Все чаты»; во время разбора круг заполняется кольцом с процентом) и «Новый анализ» в боковой панели. Нижнего меню, плавающих кнопок и капсул нет (решение 13.11). Идущий разбор вне главной на телефоне — тонкая линия по верхнему краю экрана (`AppHeader`), на обновляемом отчёте — строка на постере; любая кнопка «Разобрать» с процентом открывает один лист «Разбираем переписку» с отменой (`ReportActionsHost`).

Основной язык интерфейса — русский, английский тоже поддерживается. Владелец пишет по-русски, отвечать ему по-русски.

Направление с 11.11 — «люди — постеры, интерфейс — чернила на бумаге» (`docs/design-system.md`). Метод доводки один, скиллы не смешиваем: `unslop` (направление и порядок проходов: отступы → цвет → значки → тексты → шрифт → раскладка → детали → визуал → движение) и `frontend-design` от Anthropic (принципы выбора); `emil-design-eng` и `apple-design` — только для движения и жестов. Проектные скиллы лежат в `.claude/skills` (локально, в git не входят: `.claude/` в `.gitignore`). ## Стек и структура

pnpm-монорепо, Node 22.

```text
apps/web         Nuxt 4 (Vue 3, Pinia), html2canvas; свой UI-кит без фреймворка, графики — свои CSS-столбики
apps/api         Fastify 5 (src/index.ts), BullMQ worker (src/worker.ts), Drizzle + PostgreSQL, Redis, teleproto (форк GramJS)
packages/shared  контракт API (zod), типы и вся аналитика отчёта — чистые функции с тестами
docs/            PRODUCT, RESEARCH, MAP, design-system, ARCHITECTURE, DEPLOY-VPS, ENVIRONMENT, SECURITY, RUNBOOK, RELEASE, ROADMAP
```

Прод — один VPS в Docker (`deploy/`: сайт, API, worker, Postgres, Redis, Caddy с HTTPS), инструкция — `docs/DEPLOY-VPS.md`; обновление на сервере — `bash /opt/tganalyzer/deploy/update.sh`.

## Запуск в демо-режиме (без Telegram)

```bash
pnpm install
cp .env.example .env     # заполнить SESSION_ENCRYPTION_KEY, JWT_SECRET, JWT_REFRESH_SECRET (openssl rand -hex 32)
docker compose up -d postgres redis
pnpm db:migrate
pnpm dev                 # web :3000, API :3001, worker
```

- `TELEGRAM_MODE=fake` включает встроенный демо-аккаунт. Входить можно с любым номером, код `12345`. Номер, оканчивающийся на `9`, дополнительно спросит пароль `secret`.
- Демо-чаты: Мила (1011, 4800 сообщений, лайм), Мама, Артём, Sofia, Дима (работа), Катя (1006), Олег, Анна. Группы: Продуктовая команда (-1002001), Семья, Бег по утрам, Weekend plans (-1002004). Каналы и бот в список не попадают.
- Демо-чаты заканчиваются сегодняшним днём (кроме тех, у кого задан `quietDays`).
- Пустые значения вида `KEY=` в `.env` считаются незаданными (так сделано в `apps/api/src/config.ts`).
- В `.env` владельца с 12.11 `DATABASE_URL` и `REDIS_URL` смотрят в локальный Docker (облачные Neon и Upstash от Railway больше не используются, их строки закомментированы). Для демо всё равно передавай их явно, переменные окружения важнее `.env`: `DATABASE_URL=postgresql://postgres:password@127.0.0.1:5432/tganalyzer REDIS_URL=redis://127.0.0.1:6379 TELEGRAM_MODE=fake`. Никогда не запускай fake-worker и `db:migrate` против облака.

**Без Docker** (облачная сессия Claude): Postgres 16 и redis-server стоят в системе. Нужно сделать `initdb` во временный каталог, создать базы `tganalyzer` и `tganalyzer_test`, запустить redis на портах 6379 и 56379, затем запустить api, worker и web через `pnpm --filter … dev`. Для e2e добавь `AUTH_RATE_LIMIT_MAX=1000` в `.env`: иначе частые входы упрутся в лимит.

## Проверки (всё должно быть зелёным перед сдачей)

```bash
pnpm lint && pnpm format:check && pnpm check     # ESLint, Prettier, TypeScript (web — nuxt typecheck)
pnpm test:unit                                   # аналитика в packages/shared
pnpm services:test && pnpm test                  # + интеграционные тесты API (Postgres :55432, Redis :56379)
pnpm test:e2e                                    # Playwright: mobile, mobile-webkit, desktop; нужен поднятый стек в fake-режиме
```

- Без Docker интеграционные тесты запускаются с `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- e2e против уже запущенного стека: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` (из `apps/web`).
- Визуальная проверка обязательна: скриншоты Playwright на 1440×900 и 390×844 (`isMobile`), светлая и тёмная тема. Горизонтального скролла на ширине 360–430 px быть не должно.
- `pnpm lint` включает `scripts/check-tokens.mjs`: токен, который читают, но нигде не объявляют, — ошибка. Замер дизайн-системы (`apps/web/tests/visual`: `measure` + `summarize --check`) идёт в CI в джобе e2e.
- Тестовый вход (e2e, `shots`, `measure`) сначала проверяет, что API отвечает с заголовком `x-telegram-mode: fake`, и иначе отказывается: случайный номер в live-режиме получил бы настоящий код. Стек для тестов поднимай только с явным `TELEGRAM_MODE=fake` — в `.env` по умолчанию live.

## Правила кода и дизайна

- **Слова.** Процесс называется «разбор» («Новый анализ» — только имя экрана), сеанс Telegram — «сеанс», не «сессия». **Тексты** только через i18n: `apps/web/app/i18n/en.ts` — источник ключей, `ru.ts` обязан покрывать все ключи (это проверяет TypeScript). Множественное число — суффиксы `.one/.few/.many/.other` и функция `tc()`. После удаления текста удаляй и неиспользуемые ключи.
- **Цвета и размеры** только через токены `apps/web/app/assets/styles/tokens.css` (карта — `docs/design-system.md`). Никакого `color-mix()` и захардкоженных цветов в компонентах: новый оттенок — новый токен со значением для каждой темы. Компоненты читают семантические токены, не примитивы. **Цвет означает только человека** (`lib/hue.ts`: `abs(peer id) % 7`; `data-hue` переназначает `--them`, `--poster`, `--story-*`); интерфейс монохромный. Отступы только `--space-*`, радиусы `--radius-mark/well/card/sheet/pill` (8 · 12 · 24 · 32 · капсула; все кнопки — капсулы), длительности `--duration-*`, кривые `--ease-*`. Всё проверяет Stylelint в `pnpm lint`; виды кнопок, текстовые стили и радиусы — замер `apps/web/tests/visual` (`measure` + `measure:summary --check`). Тёмная тема — один раз в `:root[data-theme='dark']`. Контраст на постере считается до его самого тёмного угла (числа — `docs/design-system.md`); цвет человека всегда рядом с именем или инициалами. Hover — только в `@media (hover: hover) and (pointer: fine)`.

- **Каркас страницы.** Публичные страницы (лендинг, приватность, вход, пример `/example`, гостевая ссылка `/s/:token`, 404/ошибки, офлайн) — `layouts/default.vue`: `SiteHeader` + страница + `SiteFooter`. Шапка у них одна: слева всегда логотип `BrandLink` (знак + «TG Analyzer», он же путь домой), кружка «назад» нет. Справа только «Войти» — `UiButton` secondary `sm` (тому, кто уже вошёл, — «Мои отчёты» по cookie-подсказке `tg-analyzer-signed-in`, которую ставит стор входа); языка и темы в шапке нет (язык при первом визите берётся из браузера, `Accept-Language`, тема — из системы; меняются в аккаунте); её нет на лендинге (там «Войти через Telegram» на единственном экране), на странице входа и офлайн. Подвал `SiteFooter` — только у лендинга на ПК, одной строкой внутри экрана: «Приватность», канал и «Поддержать» (по `NUXT_PUBLIC_CHANNEL_URL` / `NUXT_PUBLIC_SUPPORT_URL`), строка про Telegram API. На телефоне и на остальных страницах подвала нет: на лендинге приватность — ссылка в подзаголовке, строка про Telegram API — в конце «Приватности». Над постером (пример, гость) на телефоне шапка — кусок самого постера (цвет, свет и зерно на своём месте, `usePosterHeader`), постер уходит под неё, все элементы — его чернила (`--on-poster`); на ПК постер — скруглённая карточка под обычной шапкой. Имени чата в шапке нет (оно крупно на постере; у примера это h1 постера); после постера — стекло, как в кабинете (`--header-glass` + `--glass-filter` + `--divider-bottom`). Публичные страницы свой `UiPageBar` не телепортируют. Кабинет — `layouts/workspace.vue`: на ПК `AppSidebar` — непрозрачная колонка на всю высоту (`--sidebar-glass`), волосяная линия справа: логотип, главная кнопка «Новый анализ», «Главная», отчёты (личные, группы); фон колонки — бумага страницы, открытый экран — белая строка с волосяной кромкой (`--sidebar-selection` + `--ring-card`). `AppHeader` на телефоне и планшете: главная — знак и аватар, внутренний экран — «назад», заголовок по центру и действие справа; при прокрутке — стекло (`--header-glass` + `--glass-filter` + `--divider-bottom`). Над постером отчёта (`[data-poster]`, `usePosterHeader`) шапка отдаёт свою высоту и висит поверх постера его же куском (постер — материал до самого края экрана; имя при прокрутке уходит под её край), кнопки на нём — полупрозрачные фишки, имя визуально спрятано (h1 остаётся для экранных дикторов); после постера — стекло с именем: «большой заголовок» HIG. На телефоне отчёт ложится на постер листом со скруглёнными плечами, на ПК постер — скруглённая карточка в колонке. Заголовок экрана на ПК — `--text-h3`, аватар справа, поиска в шапке нет. Главная открывается заголовком экрана «Отчёты» (`.t-h1`) и строкой «Что вы уже узнали о своих переписках»; приветствий («Доброе утро, …») нет — заголовок называет экран. Логотип везде — `BrandLink`. Своих шапок на страницах не заводим.

- **Страница внутри каркаса:** `UiPageContainer` → `div.page` (ритм `--page-gap`) → секции `UiPageSection` (h2 стилем `.t-h3`). Заголовок экрана в кабинете и в примере отчёта — `UiPageBar`: он телепортируется в общий хедер (`#header-page` в `AppHeader` / `SiteHeader`) и несёт единственный h1, короткую строку и действия. Своих шапок на страницах кабинета не делаем. Страницы «Условия» нет. Отступы сверху и снизу задают layout-ы через `--page-top` / `--page-bottom`. `size="narrow"` ограничивает ширину контента, но он остаётся выровнен по левому краю под логотипом. Вход и статус-страницы — исключение: одна карточка по центру.
- **Типографика.** Одна гарнитура — Onest, начертания 400/500/600, иерархия размером, начертанием и цветом. Роли и классы: `--text-display/figure/h1/h2/h3/body/label/caption` и `.t-*`; рядом с `font: var(--text-h*)` стоит `--tracking-*`. Свои размеры в компонентах не задаём. Ссылка в тексте — `.link`.

- **Компоненты.** UI-кит лежит в `components/ui` и вызывается с префиксом `Ui…` (`UiButton`, `UiListRow`, `UiGroup`). Остальные компоненты вызываются по имени файла. Иконки импортируются только из `lib/icons.ts` (Lucide).
- **Числа** выводятся табличными цифрами основного шрифта. Правило стоит в `base.css` на `#__nuxt *` и `#teleports *`: шорткат `font:` в компонентах сбрасывает `font-variant-numeric`, а id-селектор его перебивает. Моноширинный шрифт для чисел не используется. Число и единица не разрываются (неразрывный пробел, окна времени — `.nowrap` или U+2060 вокруг тире).
- **Отчёт.** Карточка (`ReportSection`): вопрос тихой строкой → ответ одной фразой → картинка → необязательная сноска; `hero` — главная находка части; `icon` делает вопрос меткой темы, как в «Здоровье» Apple (значок без круга, цветом человека). Отчёт длинный нарочно: интересное число получает размер числа (`ReportTiles` — сетка крупных чисел), а не строку мелким шрифтом. Части (`ReportPart`) личного отчёта: «Вы и {имя}», «Время», «Как говорите», «О чём» (у группы — «Люди», «Общение», «Время», «О чём»); части «Главное» нет (решение C6), каждое число — один раз: баланс с числами сообщений открывает «Вы и {имя}» постером части (`ReportSplit`), дни подряд — постер календаря в «Времени», самый насыщенный день — в рекордах. Одна подпись на метрику и у гостя: «Самый насыщенный день», «Писали друг другу N из M дней». «Оценка отношений»: ярлык («Тёплые») — число карточки, балл — тихой строкой, четыре составляющие сеткой 2×2. Сверху `ReportPoster`, внизу `ReportEnding` («Итоги: Имя»). Отчёт показывает всё, что честно знает; блок без достаточных данных скрыт (пороги в `packages/shared`). Сравнения сторон — `useVersus` (`isEven`, перевес < 1.25×), «Баланс» и «Слова» — `useBalance` и `useWordsFacts` (одни для отчёта, гостя и «Итогов»).
- **Согласованность метрик.** Одна величина не может давать два разных ответа ни на одном экране, ни между отчётом, гостем и «Итогами». Окно «обычно на связи» — `derived.availabilityProfile.peakWindow` везде.
- **Листы и жесты.** Листы на телефоне (`UiBottomSheet`, `UiModalDialog` ≤ 640 px) — одна механика `useSheetDrag`: во всю ширину, прижаты к низу, ручка, смахивание вниз; шапка листа — кнопка закрытия и заголовок на одной линии. «Итоги»: удержание — пауза, смахивание вниз закрывает. Шапка над постером тает в стекло по прокрутке (`usePosterHeader`).
- **Поделиться** (`ShareDialog`): цветная плитка «Итоги» со «Смотреть», затем строки «Сохранить картинками», «Отправить», «Ссылка на отчёт» (`ShareLinkStep`: имена, слова и эмодзи, «Скопировать ссылку», 30 дней), «Угадайка» (только когда доступна). Гость (`/s/:token`, `GuestReport`) видит те же карточки в третьем лице. Групповые отчёты по ссылке не отдаём. Аккаунт — одна колонка: профиль, оформление, уведомления (когда настроен бот), ссылки на отчёты (когда они есть) (только управление: срок и выключатель; результат «Угадайки» — в «Поделиться» отчёта и сообщением бота), «Выйти». «Устройств Telegram» нет (решение 11.11).
- **«Итоги».** `useStoryFrames` собирает кадры из тех же чисел, что отчёт; `StoryFrame` рисует кадр, `ReportStory` — проигрыватель. Размеры кадра — в `cqw` корня (html2canvas считает cq-единицы от своего вьюпорта). Картинка 1080×1920 — копия `still`.
- **e2e-селекторы.** Тесты опираются на `.chat-row`, кнопки «Разобрать», «Открыть отчёт», «Поделиться» в шапке отчёта и «Смотреть итоги» в его окне, `.report-part`, строку главы `.page-bar__lede` (хелпер `openChapter` прокручивает к главе), `.stories__segment`, `.frame__title`. Вход — кнопка «Войти». Меняешь что-то из этого — правь тесты.
- **Аналитика.** Логика живёт в `packages/shared` в виде чистых функций и покрывается тестами. Чат меньше `MIN_REPORT_MESSAGES` (100) не разбираем: API отвечает `CHAT_TOO_SMALL` до списания лимита, воркер — `chat_too_small`. Производные метрики считаются при чтении (`deriveReportMetrics`), поэтому их можно улучшать без повторного анализа. Активность групп («писали в последний месяц», роли) считается от последнего сообщения в чате, а не от текущей даты.

## Git

- Работаем в `main`, владелец просит коммитить и пушить туда. Сообщения коммитов — на английском, в стиле истории репозитория (короткий заголовок о том, что стало лучше для пользователя).
- Папка проекта у владельца: `L:\tganalizer` (Windows). При работе через связь с компьютером git должен иметь право удалять lock-файлы. Без этого `commit` и `checkout` ломают репозиторий.
- Пуш идёт через Git Credential Manager владельца (токена в адресе `origin` больше нет). Секреты нигде не выводи и не копируй.

## Как сдавать работу

1. Если задача большая, сначала аудит и план, потом правки.
2. Прогнать все проверки и сделать скриншоты «после».
3. Обновить `docs/ROADMAP.md`, а при изменении архитектуры — `docs/ARCHITECTURE.md`.
4. Коммит и пуш, затем короткий отчёт владельцу: что изменилось для пользователя и что осталось.
