## Продукт

«Зеркало ваших переписок»: человек входит через Telegram, выбирает личный чат или группу и получает понятный отчёт. В отчёте баланс переписки, скорость ответов, ритм по часам и дням, частые слова и эмодзи, разговоры и динамика. Для групп добавляются роли участников, связи и общий словарь. «Итоги» — сторис в стиле Spotify Wrapped, которые можно сохранить картинкой 1080×1920 или отправить.

Главное обещание — приватность: тексты сообщений не сохраняются, в базе лежит только агрегированный отчёт, а удалить всё можно в один клик.

Главный объект — отчёт по чату. Главная страница отвечает на два вопроса: «что я уже узнал» (карточки отчётов) и «что ещё можно разобрать» (список чатов).

Основной язык интерфейса — русский, английский тоже поддерживается. Владелец пишет по-русски, отвечать ему по-русски.

## Стек и структура

pnpm-монорепо, Node 22.

```text
apps/web         Nuxt 4 (Vue 3, Pinia), ECharts, html2canvas; свой UI-кит без фреймворка
apps/api         Fastify 5 (src/index.ts), BullMQ worker (src/worker.ts), Drizzle + PostgreSQL, Redis, gramjs
packages/shared  контракт API (zod), типы и вся аналитика отчёта — чистые функции с тестами
docs/            ARCHITECTURE, DEPLOY, ENVIRONMENT, SECURITY, RUNBOOK, UX-REVIEW, ROADMAP
```

Деплой: Railway, три сервиса из одного репозитория (`railway.json` + `scripts/service.mjs`, процесс выбирается через `START_SERVICE=api|worker|web`). Подробности в `docs/DEPLOY.md`.

## Запуск в демо-режиме (без Telegram)

```bash
pnpm install
cp .env.example .env     # заполнить SESSION_ENCRYPTION_KEY, JWT_SECRET, JWT_REFRESH_SECRET (openssl rand -hex 32)
docker compose up -d postgres redis
pnpm db:migrate
pnpm dev                 # web :3000, API :3001, worker
```

- `TELEGRAM_MODE=fake` включает встроенный демо-аккаунт. Входить можно с любым номером, код `12345`. Номер, оканчивающийся на `9`, дополнительно спросит пароль `secret`.
- Демо-чаты: Мила (1001, 4800 сообщений), Мама, Артём, Sofia, Дима (работа), Катя (1006), Олег, Анна. Группы: Продуктовая команда (-1002001), Семья, Бег по утрам, Weekend plans (-1002004). Каналы и бот в список не попадают.
- Демо-чаты заканчиваются сегодняшним днём (кроме тех, у кого задан `quietDays`).
- Пустые значения вида `KEY=` в `.env` считаются незаданными (так сделано в `apps/api/src/config.ts`).
- ⚠️ В `.env` владельца `DATABASE_URL` и `REDIS_URL` смотрят в облачные Neon и Upstash. Для локального демо передавай их явно, переменные окружения важнее `.env`: `DATABASE_URL=postgresql://postgres:password@127.0.0.1:5432/tganalyzer REDIS_URL=redis://127.0.0.1:6379 TELEGRAM_MODE=fake`. Никогда не запускай fake-worker и `db:migrate` против облака.

**Без Docker** (облачная сессия Claude): Postgres 16 и redis-server стоят в системе. Нужно сделать `initdb` во временный каталог, создать базы `tganalyzer` и `tganalyzer_test`, запустить redis на портах 6379 и 56379, затем запустить api, worker и web через `pnpm --filter … dev`. Для e2e добавь `AUTH_RATE_LIMIT_MAX=1000` в `.env`: иначе частые входы упрутся в лимит.

## Проверки (всё должно быть зелёным перед сдачей)

```bash
pnpm lint && pnpm format:check && pnpm check     # ESLint, Prettier, TypeScript (web — nuxt typecheck)
pnpm test:unit                                   # аналитика в packages/shared
pnpm services:test && pnpm test                  # + интеграционные тесты API (Postgres :55432, Redis :56379)
pnpm test:e2e                                    # Playwright, mobile + desktop; нужен поднятый стек в fake-режиме
```

- Без Docker интеграционные тесты запускаются с `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- e2e против уже запущенного стека: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` (из `apps/web`).
- Визуальная проверка обязательна: скриншоты Playwright на 1440×900 и 390×844 (`isMobile`), светлая и тёмная тема. Горизонтального скролла на ширине 360–430 px быть не должно.

## Правила кода и дизайна

- **Тексты** только через i18n: `apps/web/app/i18n/en.ts` — источник ключей, `ru.ts` обязан покрывать все ключи (это проверяет TypeScript). Множественное число — суффиксы `.one/.few/.many/.other` и функция `tc()`. После удаления текста удаляй и неиспользуемые ключи.
- **Цвета и размеры** только через токены `apps/web/app/assets/styles/tokens.css` (направление «Портрет», docs/design-system.md). Никакого `color-mix()` и захардкоженных цветов в компонентах: новый оттенок — новый токен со значением для каждой темы. Токены в три слоя: примитивы (`--gray-*`, `--night-*`, `--hue-<red|orange|violet|green|teal|blue|pink>-*`, `--red-*`, `--amber-*`, `--lime-brand` только для логотипа) → семантика → компонентные; компоненты читают только семантику. **Цвет означает только человека:** интерфейс и действия монохромны; у каждого человека свой цвет, тот же по семье, что в Telegram (`lib/hue.ts`: `abs(peer id) % 7`). `data-hue` на `<html>` (отчёт, пример, публичная ссылка) или на элементе (плитки главной) переназначает `--them`, `--poster`, `--room`, `--story-*`; производные токены переобъявлены в тех же блоках. В графиках «вы» — `--you` (чернила), собеседник — `--them`, весь чат — `--chart-neutral(-strong)`, интенсивность — нейтральная `--heat-0…4`. Колонка — `--page-max` и `--page-gutter`. Радиусы `--radius-mark/xs/sm/md/lg/xl/full` = 4/8/12/16/24(телефон 20)/32/pill, колодец — `--radius-inner`; отступы только `--space-*` (сетка 8, полушаги 4/12, `--space-0-5` = 2 px; `--space-5` нет); аватары `--avatar-*`, диалоги `--dialog-*`, обводки `--ring-*`/`--divider-*`, длительности `--duration-*`, кривые `--ease-*` и `--spring-snappy`, крутилка — только `.spinner`. Всё проверяет Stylelint в `pnpm lint`. Тёмная тема — один раз в `:root[data-theme='dark']`. Hover — только в `@media (hover: hover) and (pointer: fine)`.

- **Каркас страницы.** Публичные страницы (лендинг, вход, FAQ, пример, 404/ошибки) — `layouts/default.vue`: `SiteHeader` + страница + `SiteFooter`. Кабинет — `layouts/workspace.vue`: на ПК `AppSidebar` — непрозрачная колонка на всю высоту (`--sidebar-glass`), волосяная линия справа: логотип, главная кнопка «Новый анализ», «Главная», отчёты (личные, группы); открытый экран — белая плашка с `--shadow-segment`. `AppHeader` прозрачен; при прокрутке — стекло (`--toolbar-glass` + `--glass-filter` + `--divider-bottom`). Над постером отчёта (`[data-poster]`, `usePosterHeader`) шапка принимает его цвет и визуально прячет имя (h1 остаётся для экранных дикторов), после постера — стекло с именем: «большой заголовок» HIG. Заголовок экрана на ПК — `--text-h3`, аватар справа, поиска в шапке нет. Главная открывается приветствием (`.t-h1`), h1 «Главная» — только для дикторов (`UiPageBar untitled`). На телефоне и планшете — одна шапка. Логотип везде — `BrandLink`. Своих шапок на страницах не заводим.

- **Страница внутри каркаса:** `UiPageContainer` → `div.page` (ритм `--page-gap`) → секции `UiPageSection` (h2 стилем `.t-h3`). Заголовок экрана в кабинете и в примере отчёта — `UiPageBar`: он телепортируется в общий хедер (`#header-page` в `AppHeader` / `SiteHeader`) и несёт единственный h1, короткую строку и действия. Своих шапок на страницах кабинета не делаем. FAQ оставляет `UiPageHeader` в странице. Страницы «Условия» нет. Отступы сверху и снизу задают layout-ы через `--page-top` / `--page-bottom`. `size="narrow"` ограничивает ширину контента, но он остаётся выровнен по левому краю под логотипом. Вход и статус-страницы — исключение: одна карточка по центру.
- **Типографика.** Одна гарнитура — Onest (`--font-sans`; `--font-display` — её алиас), иерархия размером, начертанием и цветом (docs/design-system.md §3). Начертания 400 (чтение), 500 (интерфейс), 600 (заголовки и числа). Роли: `--text-display` (имя на постере, лендинг), `--text-figure`, `--text-h1/h2/h3`, `--text-title`, `--text-body`, `--text-ui`, `--text-small`, `--text-caption`; межстрочные на сетке 4. Классы `.t-display/.t-figure/.t-h1/.t-h2/.t-h3/.t-title/.t-ui/.t-small/.t-small-strong/.t-caption/.t-lede/.t-emoji` несут трекинг; рядом с `font: var(--text-h*)` всегда стоит `--tracking-*`. Свои размеры в компонентах не задаём. Живой UI-кит — `/kit` в dev-режиме. Моноширинного шрифта, надзаголовков-«киккеров», нумерации частей, строк через «·» и декоративных иконок у заголовков нет. Ссылка в тексте — `.link`.

- **Компоненты.** UI-кит лежит в `components/ui` и вызывается с префиксом `Ui…` (`UiButton`, `UiSegmentedControl`). Остальные компоненты вызываются по имени файла. Иконки импортируются только из `lib/icons.ts` (Lucide).
- **Числа** выводятся табличными цифрами основного шрифта. Правило стоит в `base.css` на `#__nuxt *` и `#teleports *`: шорткат `font:` в компонентах сбрасывает `font-variant-numeric`, а id-селектор его перебивает. Моноширинный шрифт для чисел не используется. Число и единица не разрываются (неразрывный пробел, окна времени — `.nowrap` или U+2060 вокруг тире).
- **Карточка отчёта** (`ReportSection`) — вопрос тихой строкой (`--text-ui`, серый), ответ одной фразой (`answer`, `--text-h2`), необязательная сноска (`text`), картинка. Части отчёта (`ReportPart`) — заголовок `.t-h1` без номеров. Верх отчёта — `ReportPoster` на всю ширину под шапкой: имя `--text-display`, «N сообщений с даты», зеркальный пульс («вы» сверху, собеседник снизу) и главы, если их три и больше. Строки сторон внизу нет: стороны подписаны в картинке. Одно главное число — `--text-figure`, подписи `--text-small`, оси `--text-caption`, эмодзи `--emoji-size`, иконки `icon-md`/`icon-lg`. Primary-кнопка — одна на экран.

- **Плитки.** Все плитки белые (`.tile`) на «комнате» человека (`--room`). `tone="ink"` у `ReportSection` красит плитку в цвет постера — не больше одной на часть («Круглые сообщения», «Слово переписки»). Плиток внутри плиток нет: группы значений («Рекорды», «Номинации») — сетки с волосяными линиями `--divider-*`. Карточки части (`ReportPart columns`) раскладывает `useMasonry`: две колонки на ≥901 px. Полоски-пропорции — `--bar-height` (8 px), pill. Сравнение сторон — `ReportLine`, строки — `.report-rows*`, аватар стороны — `ReportSideAvatar` (`UiAvatar side`). Аватары — цвет человека мягким вертикальным градиентом (`--avatar-N-bg` → `--avatar-N-glow`), как в Telegram.

- **Сравнения «вы против собеседника»** считает только `useVersus`. Порядок «Вы двое» (`ReportDuel`, файлы `components/report/duel/*`): «Кто отвечает быстрее» (ответ и `ReportLine`; при паритете вместо полоски два времени с аватарами), grey «Ваши привычки» (кто начинает, кто смеётся и — если у голосовых нет длительности — кто чаще шлёт голосовые), квадраты вопросов (не больше ~100), стикеры строками по сторонам (по 4, аватар слева), пьедесталы реакций (ваши — чернила, собеседника — его цвет), одна карточка голоса (ответ, `ReportLine` длительностей, факты «Вместе» и «Самое длинное»), «Доброе утро и спокойной ночи», «Кто открывает и закрывает день». Служебной строки «Нет в этом чате…» нет. `ReportLine` не рисует отрезок для нуля и ставит «—». При паритете у каждой карточки своя фраза (`report.fmt.*Even`, «Идеальный баланс», «Отвечаете синхронно»…). «О чём»: «Слово переписки» (плитка цвета постера, слово в `--text-figure`, сколько раз, места 2–4 под линией), «Ваш словарь» (`splitVocabulary`: строки «только вы / только собеседник» и «Общие»), «Любимые эмодзи» строками с `ReportLine`. Верх отчёта — `ReportPoster` (см. «Карточка отчёта»); «Кто пишет больше» — первая карточка «Вы двое» («51 / 49», чужая доля цветом человека, `ReportLine`). Под постером после повторного анализа — белая полоса «С прошлого анализа» (`ReportSince`: новые сообщения, ваш ответ, кто начинает; без новых сообщений её нет). «Время»: «Ваше время», «Ваши рекорды», «Круглые сообщения» (плитка цвета постера) (`ReportMilestones`: вехи из `milestones` и прогноз следующей `forecastMilestone`), «Активность по дням» — календарь месяцами (`ActivityHeatmap`, на телефоне 3 в ряд и последние 6) с ответом «Писали друг другу N из M дней». «Чем выделяется этот чат» убран. Главная — «Сводка»: «Закреплённые» (`PinnedPeople`, закреплённые в Telegram чаты) → «Главное» (`HomeEvents` по `deriveHomeEvents` из shared, плитки белые с аватаром и цветом человека: «Ваши 30 дней» полосками в цветах чатов, новые сообщения после отчёта, ответ на угадайку, ближайшее круглое сообщение, самый активный чат без отчёта — каждое только когда есть что сказать) → «Отчёты» карточками. В группе лидеры по привычкам — сетка `GroupAwards`; «Самый активный» называем только при перевесе ≥1.25× над следующим.
- **Согласованность метрик.** Одна величина не может давать два разных ответа ни на одном экране, ни между отчётом и «Итогами» (вопросы — всегда серии `questionTurns`; время суток — `lib/persona.ts` от `peakWindow`; «поровну» — `isEven` из `useVersus`, перевес < 1.25×; серия во всю историю не повторяет календарь). Окно «обычно на связи» берётся из `derived.availabilityProfile.peakWindow` везде: в KPI, во вкладке «Активность» и в «Итогах».
- **Листы и жесты.** Все листы на телефоне (`UiBottomSheet`, `UiModalDialog` ≤ 640 px) — одна механика `useSheetDrag`: во всю ширину, прижаты к низу, без зазоров по бокам и снизу (решение владельца), ручка, смахивание вниз от точки отпускания. «Итоги»: удержание — пауза без перелистывания, смахивание вниз закрывает. Строка чата: `:active` и своё долгое нажатие (450 мс) вместо `contextmenu`. «Назад» — pop. Шапка над постером тает в стекло по прокрутке (`usePosterHeader`, `--poster-progress`). Конец отчёта — `ReportEnding` (постер с «Смотреть итоги» и «Поделиться»); карточки «Отчётов» на главной ≥ 641 px — мини-постеры; обложка «Итогов» — постер с именем. Знак — зеркальный пульс. Подробно — docs/design-system.md и docs/DESIGN-REVIEW-ROUND-2.md.
- **Каркас v3 «Сначала главное»** (docs/proposals/frame-v3-story-first.md, принят 08.11): под постером «Главное о вас двоих» (`ReportHighlights`), у глав ответ одной фразой — всё из `useChapterHeadlines`. На телефоне шапка отчёта — «назад», капсула с главой и «Поделиться» (вариант 2a), лист глав по касанию капсулы, полосы вкладок нет. «Смотреть итоги» — на постере. Сравнение сторон — плашка «Б» в `ReportLine` (подписи внутри, `--on-you/--on-them`), «Кто отвечает быстрее» — «×3». «Круглые сообщения» удалены. Конец отчёта — постер «Итоги» и «Кого разобрать следующим». В «Итогах» — кнопка паузы и «Вся глава». Главная: «Сейчас главное», «Отчёты» мини-постерами, «Ещё не разобраны».
- **Телефон.** Отчёт — одна длинная страница из трёх частей (`ReportPart`, якоря `#part-<id>`): «Вы двое / Время / О чём», в группе «Люди / Общение / Время». `ReportNav` — закреплённая якорная навигация на всю ширину телефона, подсвечивает раздел при прокрутке. На отчёте, `/new` и в аккаунте — стрелка «назад» (`UiPageBar back`). В шапке отчёта: назад, аватар, имя и одна кнопка «Поделиться» (`ShareDialog`: превью «Итогов», «Смотреть итоги», «Сохранить картинками», «Отправить» там, где браузер умеет делиться файлами; под линией «По ссылке» — «Ссылка на отчёт» и «Угадайка» вторым шагом той же модалки, публичная страница `/s/:token`; групповые отчёты по ссылке не отдаём). «Разобрать заново» — в меню строки чата. Кнопки удаления на странице отчёта нет: удаляют из меню строки чата на «Новом анализе» и в аккаунте.
- **«Итоги».** `ReportStory.vue` собирает слайды, `StorySlide.vue` их рисует. Личный чат — четыре плотных слайда (обложка, «Вы двое», «Ваше время», «О чём»), не больше трёх рядов плиток на слайд: всё должно влезать в 9:16 между безопасными зонами. Сравнение сторон — блок `split`. Размеры задаются в `cqmin`. Контейнером служит корень `.story-slide`, а у самого корня не должно быть свойств в cq-единицах: html2canvas посчитает их от своего вьюпорта, и экспорт поедет. Экспорт рендерит отдельную копию с `still` (без анимации).
- **e2e-селекторы.** Тесты опираются на `.chat-row`, `.home-event__analyse` («Разобрать чат» в плитке «Сейчас»), кнопки «Разобрать», «Открыть отчёт», «Поделиться» в шапке отчёта и «Смотреть итоги» в его окне, на ПК роли `tab` у `ReportNav`, на телефоне — капсула `.capsule` и строки листа `.chapters__row` (хелпер `openChapter`), `.stories__segment` и `.story-slide__title`. Меняешь что-то из этого — правь тесты.
- **Аналитика.** Логика живёт в `packages/shared` в виде чистых функций и покрывается тестами. Производные метрики считаются при чтении (`deriveReportMetrics`), поэтому их можно улучшать без повторного анализа. Активность групп («писали в последний месяц», роли) считается от последнего сообщения в чате, а не от текущей даты.

## Git

- Работаем в `main`, владелец просит коммитить и пушить туда. Сообщения коммитов — на английском, в стиле истории репозитория (короткий заголовок о том, что стало лучше для пользователя).
- Папка проекта у владельца: `L:\tganalizer` (Windows). При работе через связь с компьютером git должен иметь право удалять lock-файлы. Без этого `commit` и `checkout` ломают репозиторий.
- ⚠️ В `origin` вписан GitHub-токен прямо в URL. Владельцу рекомендовано отозвать токен и подключить GitHub к Claude. Токен нигде не выводи и не копируй.

## Как сдавать работу

1. Если задача большая, сначала аудит и план, потом правки.
2. Прогнать все проверки и сделать скриншоты «после».
3. Обновить `docs/ROADMAP.md`, а при изменении архитектуры — `docs/ARCHITECTURE.md`.
4. Коммит и пуш, затем короткий отчёт владельцу: что изменилось для пользователя и что осталось.
