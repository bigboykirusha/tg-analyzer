## Продукт

«Зеркало ваших переписок»: человек входит через Telegram, выбирает личный чат или группу и получает понятный отчёт. В отчёте баланс переписки, скорость ответов, ритм по часам и дням, частые слова и эмодзи, разговоры и динамика. Для групп добавляются роли участников, связи и общий словарь. «Итоги» — сторис в стиле Spotify Wrapped, которые можно сохранить картинкой 1080×1920 или отправить.

Главное обещание — приватность: тексты сообщений не сохраняются, в базе лежит только агрегированный отчёт. Отчёт удаляется из своего меню вместе со ссылками; «удалить всё» и «отключить Telegram» владелец не хочет. Фильтра мата нет нигде (решение 11.11).

Главный объект — отчёт по чату. Главная страница — «что я уже узнал»: плитки отчётов (у новичка — «С кого начнём?» и сразу весь список чатов, `HomeFirstRun`). На телефоне каждая плитка на всю ширину: аватар слева от имени и числа сообщений (без «Группа»), пульс под ними; «новых» на плитке нет (16.11): что в чате появились сообщения после отчёта, говорит сам отчёт (`ReportChange`, «Обновить»); с пяти отчётов на телефоне плитки — компактные строки (`HomeCard compact`). Что ещё разобрать: на телефоне — полоса вдоль нижнего края главной с одной залитой кнопкой «Разобрать чат» (`HomeActionBar`), она открывает выбор чата («Выберите чат») отдельной страницей `/new` (решение 16.11: вытягиваемый лист чатов убран как неуместная для браузера механика); на ПК — кнопка «Разобрать чат» в боковой панели (экран выбора — «Выберите чат») (ленты «Разобрать ещё» нет). Нижнего меню и плавающих кнопок нет (решение 13.11): полоса — до самого края, как верх листа: его материал, скруглённые плечи и тень (17.11). Идущий разбор на главной телефона — капсула в нижней полосе вместо кнопки «Разобрать чат» (`AnalysisPill`, решение 14.11): цвет человека, маленький пульс прочитанного (воркер шлёт `progress.pulse`), процент; одна строка высотой с кнопку; касание открывает лист «Разбираем переписку»; разбор, начатый на `/new`, возвращает телефон на главную; готово — «Открыть» на отступе аватара, отчёт ложится плиткой; переходы между экранами — обычная навигация, без общих элементов (решение 17.11: View Transitions убраны как ненадёжные). На ПК — сама будущая плитка отчёта (`AnalysisTile`): стоит там, где ляжет отчёт, её пульс дорисовывается от сегодня назад, впереди точки. Уведомления — баннеры сверху без кнопок (`ToastProvider`), по одному: новый заменяет прежний и не закрывает кнопки шапки (18.11): о человеке — в его цвете, остальное — серые; «Отчёт готов» на главной не приходит. События человека (отчёт готов, угадайка, ссылки) — список `pages/notifications.vue` и web push (решение 14.11): service worker `public/sw.js`, `usePush`, `notify/PushRow` («Включить» — в «Уведомлениях», в аккаунте и в листе разбора; на iPhone вне экрана «Домой» — подсказка, как установить, iOS 16.4+), отправка — `apps/api/src/modules/notify/push.ts` из `notify()`. Бот (`notify/bot.ts`) — только новости подписчикам (рассылка `apps/api/src/broadcast.ts`) и «Сообщить о проблеме»; персональных сообщений и входа на сайт через бота нет. У списка чатов только поиск, фильтра «Все / Личные / Группы» нет (решение 14.11). Вне главной на телефоне — тонкая линия по верхнему краю экрана (`AppHeader`), на обновляемом отчёте — строка на постере; плитка и любая кнопка «Разобрать» с процентом открывают один лист «Разбираем переписку» с пульсом и отменой (`ReportActionsHost`).

Основной язык интерфейса — русский, английский тоже поддерживается. Владелец пишет по-русски, отвечать ему по-русски.

## Дизайн-скиллы

Направление с 11.11 — «люди — постеры, интерфейс — чернила на бумаге» (`docs/design-system.md`). Метод доводки один, скиллы не смешиваем: `unslop` (направление и порядок проходов: отступы → цвет → значки → тексты → шрифт → раскладка → детали → визуал → движение) и `frontend-design` от Anthropic (принципы выбора); `emil-design-eng` и `apple-design` — только для движения и жестов. Проектные скиллы лежат в `.claude/skills` (локально, в git не входят: `.claude/` в `.gitignore`). Impeccable и Taste не ставим: первый дублирует frontend-design и добавляет хуки с бинарником, второй — для рекламных лендингов с генерацией картинок.

## Стек и структура

pnpm-монорепо, Node 22.

```text
apps/web         Nuxt 4 (Vue 3, Pinia), html2canvas; свой UI-кит без фреймворка, графики — свои CSS-столбики
apps/api         Fastify 5 (src/index.ts), BullMQ worker (src/worker.ts), Drizzle + PostgreSQL, Redis, teleproto (форк GramJS)
packages/shared  контракт API (zod), типы и вся аналитика отчёта — чистые функции с тестами
docs/            PRODUCT, RESEARCH, MAP, design-system, ARCHITECTURE, DEPLOY-VPS, ENVIRONMENT, SECURITY, RUNBOOK, RELEASE, ROADMAP
```

Прод — один VPS в Docker (`deploy/`: сайт, API, worker, Postgres, Redis, Caddy с HTTPS), инструкция — `docs/DEPLOY-VPS.md`; обновление на сервере — `bash /opt/tganalyzer/deploy/update.sh`.

## Запуск в демо-режиме (без Telegram)

```bash
pnpm install
cp .env.example .env     # заполнить SESSION_ENCRYPTION_KEY, JWT_SECRET, JWT_REFRESH_SECRET (openssl rand -hex 32)
docker compose up -d postgres redis
pnpm db:migrate
pnpm dev                 # web :3000, API :3001, worker
```

- `TELEGRAM_MODE=fake` включает встроенный демо-аккаунт. Входить можно с любым номером, код `12345`. Номер, оканчивающийся на `9`, дополнительно спросит пароль `secret`.
- Демо-чаты: Мила (1011, 4800 сообщений, лайм), Мама, Артём, Sofia, Дима (работа), Катя (1006), Олег, Анна. Группы: Продуктовая команда (-1002001), Семья, Бег по утрам, Weekend plans (-1002004). Каналы и бот в список не попадают.
- Демо-чаты заканчиваются сегодняшним днём (кроме тех, у кого задан `quietDays`).
- Пустые значения вида `KEY=` в `.env` считаются незаданными (так сделано в `apps/api/src/config.ts`).
- В `.env` владельца с 12.11 `DATABASE_URL` и `REDIS_URL` смотрят в локальный Docker (облачные Neon и Upstash от Railway больше не используются, их строки закомментированы). Для демо всё равно передавай их явно, переменные окружения важнее `.env`: `DATABASE_URL=postgresql://postgres:password@127.0.0.1:5432/tganalyzer REDIS_URL=redis://127.0.0.1:6379 TELEGRAM_MODE=fake`. Никогда не запускай fake-worker и `db:migrate` против облака.

**Без Docker** (облачная сессия Claude): Postgres 16 и redis-server стоят в системе. Нужно сделать `initdb` во временный каталог, создать базы `tganalyzer` и `tganalyzer_test`, запустить redis на портах 6379 и 56379, затем запустить api, worker и web через `pnpm --filter … dev`. Для e2e добавь `AUTH_RATE_LIMIT_MAX=1000` в `.env`: иначе частые входы упрутся в лимит.

## Проверки (всё должно быть зелёным перед сдачей)

```bash
pnpm lint && pnpm format:check && pnpm check     # ESLint, Prettier, TypeScript (web — nuxt typecheck)
pnpm test:unit                                   # аналитика в packages/shared
pnpm services:test && pnpm test                  # + интеграционные тесты API (Postgres :55432, Redis :56379)
pnpm test:e2e                                    # Playwright: mobile, mobile-webkit, desktop; нужен поднятый стек в fake-режиме
```

- Без Docker интеграционные тесты запускаются с `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- e2e против уже запущенного стека: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` (из `apps/web`).
- Визуальная проверка обязательна: скриншоты Playwright на 1440×900 и 390×844 (`isMobile`), светлая и тёмная тема. Горизонтального скролла на ширине 360–430 px быть не должно.
- `pnpm lint` включает `scripts/check-tokens.mjs`: токен, который читают, но нигде не объявляют, — ошибка. Замер дизайн-системы (`apps/web/tests/visual`: `measure` + `summarize --check`) идёт в CI в джобе e2e.
- Тестовый вход (e2e, `shots`, `measure`) сначала проверяет, что API отвечает с заголовком `x-telegram-mode: fake`, и иначе отказывается: случайный номер в live-режиме получил бы настоящий код. Стек для тестов поднимай только с явным `TELEGRAM_MODE=fake` — в `.env` по умолчанию live.

## Правила кода и дизайна

- **Слова.** Процесс называется «разбор» (кнопка — «Разобрать чат», экран выбора чата — «Выберите чат»; «Новый анализ» в интерфейсе больше нет), сеанс Telegram — «сеанс», не «сессия». **Тексты** только через i18n: `apps/web/app/i18n/en.ts` — источник ключей, `ru.ts` обязан покрывать все ключи (это проверяет TypeScript). Множественное число — суффиксы `.one/.few/.many/.other` и функция `tc()`. После удаления текста удаляй и неиспользуемые ключи.
- **Цвета и размеры** только через токены `apps/web/app/assets/styles/tokens.css` (карта — `docs/design-system.md`). Никакого `color-mix()` и захардкоженных цветов в компонентах: новый оттенок — новый токен со значением для каждой темы. Компоненты читают семантические токены, не примитивы. **Цвет означает только человека** (`lib/hue.ts`: `abs(peer id) % 7`; `data-hue` переназначает `--them`, `--poster`, `--story-*`); интерфейс монохромный. Отступы только `--space-*`, радиусы `--radius-mark/well/card/poster/sheet/pill` (8 · 12 · 16 · 24 · 32 · капсула; все кнопки — капсулы), длительности `--duration-*`, кривые `--ease-*`. Всё проверяет Stylelint в `pnpm lint`; виды кнопок, текстовые стили и радиусы — замер `apps/web/tests/visual` (`measure` + `measure:summary --check`). Тёмная тема — один раз в `:root[data-theme='dark']`. Контраст считается по APCA, не по WCAG 2 (решение 17.11): `scripts/check-contrast.mjs` в `pnpm lint` проверяет пары токенов обеих тем и семи постеров (основной текст Lc ≥ 75, тихий текст и подписи ≥ 60, шевроны ≥ 30; числа — `docs/design-system.md`); постер в обеих темах один, дневной; цвет человека всегда рядом с именем или инициалами. Hover — только в `@media (hover: hover) and (pointer: fine)`.

- **Каркас страницы.** Публичные страницы (лендинг, приватность, вход, пример `/example`, гостевая ссылка `/s/:token`, 404/ошибки, офлайн) — `layouts/default.vue`: `SiteHeader` + страница + `SiteFooter`. Шапка у них одна: слева всегда логотип `BrandLink` (знак + «TGDuet», он же путь домой), кружка «назад» нет. Справа только «Войти» — `UiButton` secondary `sm` (тому, кто уже вошёл, — «Мои отчёты» по cookie-подсказке `tg-analyzer-signed-in`, которую ставит стор входа); языка и темы в шапке нет (язык при первом визите берётся из браузера, `Accept-Language`, тема — из системы; меняются в аккаунте); её нет на лендинге (там «Войти через Telegram» на единственном экране), на странице входа и офлайн. Подвал `SiteFooter` — только у лендинга на ПК, одной строкой внутри экрана: «Приватность», канал и «Поддержать» (по `NUXT_PUBLIC_CHANNEL_URL` / `NUXT_PUBLIC_SUPPORT_URL`), строка про Telegram API. На телефоне и на остальных страницах подвала нет: на лендинге приватность — ссылка в подзаголовке, «неофициальный сервис, работает через Telegram API» — последняя фраза описания «Приватности»; на экране входа строки про Telegram API нет, а под полем номера — тихая строка «Тексты сообщений не сохраняются — только числа отчёта» со ссылкой на «Приватность» (14.11: вход — самая тревожная точка). Над постером (пример, гость) на телефоне шапка — кусок самого постера (цвет, свет и зерно на своём месте, `usePosterHeader`), постер уходит под неё, все элементы — его чернила (`--on-poster`); на ПК постер — скруглённая карточка под обычной шапкой. Имени чата в шапке нет (оно крупно на постере; у примера это h1 постера); после постера — стекло, как в кабинете (`--header-glass` + `--glass-filter` + `--divider-bottom`). Публичные страницы свой `UiPageBar` не телепортируют. Кабинет — `layouts/workspace.vue`: на ПК `AppSidebar` — непрозрачная колонка на всю высоту (`--sidebar-glass`), волосяная линия справа: логотип, главная кнопка «Разобрать чат», «Главная», отчёты (личные, группы) — одна колонка на всех экранах, и на главной тоже (18.11); только у новичка на главной (она и есть список чатов) нет ни списка, ни кнопки; фон колонки — бумага страницы, открытый экран — белая строка с волосяной кромкой (`--sidebar-selection` + `--ring-card`). `AppHeader` на телефоне и планшете: главная — знак и аватар, внутренний экран — «назад», заголовок по центру и действие справа; при прокрутке — стекло (`--header-glass` + `--glass-filter` + `--divider-bottom`). Над постером отчёта (`[data-poster]`, `usePosterHeader`) шапка отдаёт свою высоту и висит поверх постера его же куском (постер — материал до самого края экрана; имя при прокрутке уходит под её край), кнопки на нём — полупрозрачные фишки, имя визуально спрятано (h1 остаётся для экранных дикторов); после постера — стекло с именем: «большой заголовок» HIG. На телефоне отчёт ложится на постер листом со скруглёнными плечами, на ПК постер — скруглённая карточка в колонке. Заголовок экрана на ПК — `--text-h1` (растёт на ПК на всех экранах, включая вход и статус-страницы), аватар справа, поиска в шапке нет. Значки-кнопки в шапках, листах и окнах («назад», «поделиться», «⋯», «закрыть») — на сером круге (`--fill-raised`), над постером — полупрозрачные фишки; без круга только колокольчик (`UiIconButton bare`). Главная открывается заголовком экрана «Отчёты» (`.t-h1`) и строкой «Что вы уже узнали о своих переписках»; приветствий («Доброе утро, …») нет — заголовок называет экран. Логотип везде — `BrandLink`. Своих шапок на страницах не заводим.

- **Страница внутри каркаса:** `UiPageContainer` → `div.page` (ритм `--page-gap`) → секции — свои `<section>` с h2 стилем `.t-h3` (отдельного компонента секции нет, 14.11). Заголовок экрана в кабинете и в примере отчёта — `UiPageBar`: он телепортируется в общий хедер (`#header-page` в `AppHeader` / `SiteHeader`) и несёт единственный h1, короткую строку и действия. Своих шапок на страницах кабинета не делаем. Страницы «Условия» нет. Отступы сверху и снизу задают layout-ы через `--page-top` / `--page-bottom`. `size="narrow"` ограничивает ширину контента, но он остаётся выровнен по левому краю под логотипом. Вход и статус-страницы — исключение: одна карточка по центру.
- **Типографика.** Одна гарнитура — Onest, начертания 400/500/600, иерархия размером, начертанием и цветом. Роли и классы: `--text-display/figure/h1/h2/h3/body/label/caption` и `.t-*`; рядом с `font: var(--text-h*)` стоит `--tracking-*`. Свои размеры в компонентах не задаём. Ссылка в тексте — `.link`.

- **Компоненты.** UI-кит лежит в `components/ui` и вызывается с префиксом `Ui…` (`UiButton`, `UiListRow`, `UiGroup`). Остальные компоненты вызываются по имени файла. Иконки импортируются только из `lib/icons.ts` (Lucide). Пустые экраны и ошибки — одна анатомия `UiEmptyState`: значок в сером круге, заголовок, строка, действие; единственное действие — чернильное; `StatusPage` публичных страниц собран из него и на ПК стоит в карточке (18.11). Действие в конце строки чата — тихая капсула sm на всех стадиях: «Разобрать» → «17 %» → «В очереди».
- **Числа** выводятся пропорциональными цифрами основного шрифта (16.11: табличная «1» оставляла дыру — «1 90 дней», «1 3:00»). Табличные — только где цифры меняются на месте или стоят столбиком: элемент с классом `.tnum` (проценты разбора, отсчёт повторной отправки кода, поле кода, столбец долей в группе). Правило стоит в `base.css` на `#__nuxt .tnum` и `#teleports .tnum`: шорткат `font:` в компонентах сбрасывает `font-variant-numeric`, а id-селектор его перебивает. Моноширинный шрифт для чисел не используется. Число и единица не разрываются (неразрывный пробел, окна времени — `.nowrap` или U+2060 вокруг тире).
- **Отчёт.** Карточка (`ReportSection`): вопрос тихой строкой → ответ одной фразой → картинка → необязательная сноска; `hero` — главная находка части; `icon` делает вопрос меткой темы, как в «Здоровье» Apple (значок без круга, цветом человека). Отчёт длинный нарочно: интересное число получает размер числа (`ReportTiles` — сетка крупных чисел), а не строку мелким шрифтом. Части (`ReportPart`) личного отчёта: «Вы и {имя}», «Время», «Как говорите», «О чём» (у группы — «Люди», «Общение», «Время», «О чём»); под постером — «Главное» (`ReportHighlights`, 14.11; плитками с 16.11): до трёх выводов — широкая плитка на материале постера и две светлые, теми же фразами, что ответы их карточек (те же функции: `useStreak`, `useWordsFacts`, `usePeakWindow`, `useBalance`), касание ведёт к карточке; полосы глав нет (убрана 17.11: капсулы над отчётом мешали; части идут подряд); над каждой частью, кроме первой, — волосяная линия; «По часам» — круг на 24 часа с окном пика (`HourlyChart`, и у групп), «Утро и ночь» — своя карточка в «Времени» (`ReportRituals`), словами, без множителей; отдельной части «Главное» нет, внутри частей каждое число — один раз: баланс с числами сообщений открывает «Вы и {имя}» постером части (`ReportSplit`), дни подряд — постер календаря в «Времени», самый насыщенный день — в рекордах. Одна подпись на метрику и у гостя: «Самый насыщенный день», «Писали друг другу N из M дней». «Оценка отношений»: ярлык («Тёплые») — число карточки, балл — тихой строкой, четыре составляющие сеткой 2×2. Сверху `ReportPoster`, внизу `ReportEnding` («Итоги: Имя»). Отчёт показывает всё, что честно знает; блок без достаточных данных скрыт (пороги в `packages/shared`). Сравнения сторон — `useVersus` (`isEven`, перевес < 1.25×), «Баланс» и «Слова» — `useBalance` и `useWordsFacts` (одни для отчёта, гостя и «Итогов»).
- **Согласованность метрик.** Одна величина не может давать два разных ответа ни на одном экране, ни между отчётом, гостем и «Итогами». Окно «обычно на связи» — `derived.availabilityProfile.peakWindow` везде.
- **Листы и жесты.** Листы на телефоне (`UiBottomSheet`, `UiModalDialog` ≤ 640 px) — одна механика `useSheetDrag`: во всю ширину, прижаты к низу, ручка, смахивание вниз; шапка листа — заголовок по центру, крестик справа, «назад» второго шага слева (решение 14.11). «Итоги»: удержание — пауза, смахивание вниз закрывает. Шапка над постером тает в стекло по прокрутке (`usePosterHeader`).
- **Поделиться** (`ShareDialog`): цветная плитка «Итоги» со «Смотреть», затем строки «Сохранить картинками», «Отправить», «Ссылка на отчёт» (`ShareLinkStep`: имена, слова и эмодзи, «Скопировать ссылку», 30 дней), «Угадайка» (всегда у личного отчёта; когда однозначных вопросов меньше трёх — выключенная строка с причиной). Вопросы угадайки (`deriveQuiz`, до 10) — числовые «кто больше?» и факты с одним ответом (кто написал первым, кто нарушил самое долгое молчание, чьё голосовое длиннее), факты всегда в игре и стоят между числами; вопрос отбрасывается, только когда стороны почти равны (меньше 2 %) или на экране числа выглядят одинаково («2 мин» и «2 мин»), близкий счёт (меньше 1,25×) в ответе называется «почти поровну»; вопросы хранятся в самой ссылке. Два способа и ничего больше (решение 17.11): «Отправить в Telegram» / «Скопировать ссылку» — играет гость, автор видит его счёт, «Новая угадайка» — новая ссылка; «Пройти самостоятельно» — та же игра на странице `/quiz/:id` (`PublicQuiz self`; на ПК — скруглённая карточка-постер в колонке, как постер отчёта), ответы сразу, ничего не отправляется и не хранится. Ставок автора и счёта против счёта нет. Игрок после выбора видит ✓ у верного, ✗ у своего неверного, оба числа и полоску сравнения, в конце — счёт и список своих ответов. На постере угадайки строки и список — в его светлом тоне и чернилах в обеих темах. Гость (`/s/:token`, `GuestReport`) видит те же карточки в третьем лице. Групповой отчёт по ссылке отдаём (с 17.11): тот же `ShareLinkStep` с выключателями «Показывать имена участников» (по умолчанию выключен: участники согласия не давали, а отправленную ссылку не отозвать) и «Показывать слова и эмодзи»; гость видит карточки `report/group/*`. Настоящие Telegram ID участников наружу не уходят никогда (`publicGroup`: p1, p2 … по активности); без имён — «Участник N», «Группа», без пар; без слов — пустые слова и эмодзи участников. Угадайки у группы нет. Аккаунт — одна колонка: профиль, оформление, «Уведомления» (одна группа: пуш этого устройства — когда настроены `VAPID_*` — и новости бота, оба выключателями), «Сообщить о проблеме» (когда настроен бот), ссылки на отчёты (когда они есть) (только управление: срок и выключатель — выключенная ссылка включается с тем же адресом, `share_links.disabled`; результат «Угадайки» — в «Поделиться» отчёта и пушем), «Выйти». «Устройств Telegram» нет (решение 11.11).
- **«Итоги».** `useStoryFrames` собирает кадры из тех же функций, что карточки отчёта (`useBalance`, `useStreak`, `useRecords`, `useFavouriteEmoji`, `useWordsFacts`, `useChatSpan`): кадр есть, только когда есть его карточка. Личный чат — до 8 кадров: обложка, баланс, дни подряд, время, самый долгий разговор, слово, эмодзи, «Всё вместе» (до шести чисел на одной картинке); группа — обложка, люди, время, слово, эмодзи, «Всё вместе». Подача «Афиша» (14.11): кадр — цвет человека и одна находка огромными чернилами, подогнанная по длине текста (`--chars`, без измерения после отрисовки) и никогда не разорванная посреди слова, под ней ответ и картинка находки. `StoryFrame` рисует кадр, `ReportStory` — проигрыватель. Размеры кадра — в `cqw` корня (html2canvas считает cq-единицы от своего вьюпорта). Картинка 1080×1920 — копия `still`.
- **e2e-селекторы.** Тесты опираются на `.chat-row`, кнопки «Разобрать», «Открыть отчёт», «Поделиться» в шапке отчёта и «Смотреть итоги» в его окне, `.report-part`, якоря частей `#part-*` и `#chapter-*` (хелпер `openCard` прокручивает к карточке), `.stories__segment`, `.frame__title`. Вход — кнопка «Войти». Меняешь что-то из этого — правь тесты.
- **Аналитика.** Логика живёт в `packages/shared` в виде чистых функций и покрывается тестами. Чат меньше `MIN_REPORT_MESSAGES` (100) не разбираем: API отвечает `CHAT_TOO_SMALL` до списания лимита, воркер — `chat_too_small`. Производные метрики считаются при чтении (`deriveReportMetrics`), поэтому их можно улучшать без повторного анализа. Активность групп («писали в последний месяц», роли) считается от последнего сообщения в чате, а не от текущей даты.

## Git

- Работаем в `main`, владелец просит коммитить и пушить туда. Сообщения коммитов — на английском, в стиле истории репозитория (короткий заголовок о том, что стало лучше для пользователя).
- Папка проекта у владельца: `L:\tganalizer` (Windows). При работе через связь с компьютером git должен иметь право удалять lock-файлы. Без этого `commit` и `checkout` ломают репозиторий.
- Пуш идёт через Git Credential Manager владельца (токена в адресе `origin` больше нет). Секреты нигде не выводи и не копируй.

## Как сдавать работу

1. Если задача большая, сначала аудит и план, потом правки.
2. Прогнать все проверки и сделать скриншоты «после».
3. Обновить `docs/ROADMAP.md`, а при изменении архитектуры — `docs/ARCHITECTURE.md`.
4. Коммит и пуш, затем короткий отчёт владельцу: что изменилось для пользователя и что осталось.
