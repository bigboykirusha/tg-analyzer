# TG Analyzer — контекст для Claude

Читай этот файл в начале каждой сессии. План и статус работ — в `docs/ROADMAP.md`. В конце сессии обнови ROADMAP.

## Продукт

«Зеркало ваших переписок»: человек входит через Telegram, выбирает личный чат или группу и получает понятный отчёт. В отчёте баланс переписки, скорость ответов, ритм по часам и дням, частые слова и эмодзи, разговоры и динамика. Для групп добавляются роли участников, связи и общий словарь. «Итоги» — сторис в стиле Spotify Wrapped, которые можно сохранить картинкой 1080×1920 или отправить.

Главное обещание — приватность: тексты сообщений не сохраняются, в базе лежит только агрегированный отчёт, а удалить всё можно в один клик.

Главный объект — отчёт по чату. Главная страница отвечает на два вопроса: «что я уже узнал» (карточки отчётов) и «что ещё можно разобрать» (список чатов).

Основной язык интерфейса — русский, английский тоже поддерживается. Владелец пишет по-русски, отвечать ему по-русски.

## Стек и структура

pnpm-монорепо, Node 22.

```text
apps/web         Nuxt 4 (Vue 3, Pinia), ECharts, html2canvas; свой UI-кит без фреймворка
apps/api         Fastify 5 (src/index.ts), BullMQ worker (src/worker.ts), Drizzle + PostgreSQL, Redis, gramjs
packages/shared  контракт API (zod), типы и вся аналитика отчёта — чистые функции с тестами
docs/            ARCHITECTURE, DEPLOY, ENVIRONMENT, SECURITY, RUNBOOK, UX-REVIEW, ROADMAP
```

Деплой: Railway, три сервиса из одного репозитория (`railway.json` + `scripts/service.mjs`, процесс выбирается через `START_SERVICE=api|worker|web`). Подробности в `docs/DEPLOY.md`.

## Запуск в демо-режиме (без Telegram)

```bash
pnpm install
cp .env.example .env     # заполнить SESSION_ENCRYPTION_KEY, JWT_SECRET, JWT_REFRESH_SECRET (openssl rand -hex 32)
docker compose up -d postgres redis
pnpm db:migrate
pnpm dev                 # web :3000, API :3001, worker
```

- `TELEGRAM_MODE=fake` включает встроенный демо-аккаунт. Входить можно с любым номером, код `12345`. Номер, оканчивающийся на `9`, дополнительно спросит пароль `secret`.
- Демо-чаты: Мила (1001, 4800 сообщений), Мама, Артём, Sofia, Дима (работа), Катя (1006), Олег, Анна. Группы: Продуктовая команда (-1002001), Семья, Бег по утрам, Weekend plans (-1002004). Каналы и бот в список не попадают.
- Демо-чаты заканчиваются сегодняшним днём (кроме тех, у кого задан `quietDays`).
- Пустые значения вида `KEY=` в `.env` считаются незаданными (так сделано в `apps/api/src/config.ts`).

**Без Docker** (облачная сессия Claude): Postgres 16 и redis-server стоят в системе. Нужно сделать `initdb` во временный каталог, создать базы `tganalyzer` и `tganalyzer_test`, запустить redis на портах 6379 и 56379, затем запустить api, worker и web через `pnpm --filter … dev`. Для e2e добавь `AUTH_RATE_LIMIT_MAX=1000` в `.env`: иначе частые входы упрутся в лимит.

## Проверки (всё должно быть зелёным перед сдачей)

```bash
pnpm lint && pnpm format:check && pnpm check     # ESLint, Prettier, TypeScript (web — nuxt typecheck)
pnpm test:unit                                   # аналитика в packages/shared
pnpm services:test && pnpm test                  # + интеграционные тесты API (Postgres :55432, Redis :56379)
pnpm test:e2e                                    # Playwright, mobile + desktop; нужен поднятый стек в fake-режиме
```

- Без Docker интеграционные тесты запускаются с `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- e2e против уже запущенного стека: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` (из `apps/web`).
- Визуальная проверка обязательна: скриншоты Playwright на 1440×900 и 390×844 (`isMobile`), светлая и тёмная тема. Горизонтального скролла на ширине 360–430 px быть не должно.

## Правила кода и дизайна

- **Тексты** только через i18n: `apps/web/app/i18n/en.ts` — источник ключей, `ru.ts` обязан покрывать все ключи (это проверяет TypeScript). Множественное число — суффиксы `.one/.few/.many/.other` и функция `tc()`. После удаления текста удаляй и неиспользуемые ключи.
- **Цвета и размеры** только через токены `apps/web/app/assets/styles/tokens.css`. Никакого `color-mix()` и захардкоженных цветов в компонентах: новый оттенок — это новый токен со значением для каждой темы. Колонка страницы задаётся через `--page-max` и `--page-gutter`, шапка и все страницы стоят в одной колонке.
- **Каркас страницы.** Публичные страницы (лендинг, вход, FAQ, условия, пример, 404/ошибки) живут в `layouts/default.vue`: `SiteHeader` + страница + `SiteFooter` (уведомление о Telegram API, документы, язык, тема). Кабинет — `layouts/workspace.vue`: `AppSidebar` на ПК, `AppHeader` (на телефоне «Новый анализ» — кнопка в шапке главной, плавающих панелей нет). Логотип везде — `BrandLink`. Своих шапок и логотипов на страницах не заводим.
- **Страница внутри каркаса:** `UiPageContainer` → `div.page` (ритм `--page-gap`) → секции `UiPageSection` (h2 стилем `.t-h3`). Заголовок экрана в кабинете и в примере отчёта — `UiPageBar`: он телепортируется в общий хедер (`#header-page` в `AppHeader` / `SiteHeader`) и несёт единственный h1, короткую строку и действия. Своих шапок на страницах кабинета не делаем. Документы (FAQ, условия) оставляют `UiPageHeader` в странице. Отступы сверху и снизу задают layout-ы через `--page-top` / `--page-bottom`. `size="narrow"` ограничивает ширину контента, но он остаётся выровнен по левому краю под логотипом. Вход и статус-страницы — исключение: одна карточка по центру.
- **Типографика — одна шкала:** `.t-h1` заголовок страницы, `.t-h2` заголовок карточки, диалога или статуса, `.t-h3` секция страницы, `.t-title` плитка или строка, `.t-lede` лид. Свои размеры заголовков в компонентах не задаём; крупный дисплейный кегль есть только у лендинга. Моноширинного шрифта и надзаголовков-«киккеров» в системе нет. Ссылка в тексте — `.link`.
- **Компоненты.** UI-кит лежит в `components/ui` и вызывается с префиксом `Ui…` (`UiButton`, `UiSegmentedControl`). Остальные компоненты вызываются по имени файла. Иконки импортируются только из `lib/icons.ts` (Lucide).
- **Числа** выводятся табличными цифрами основного шрифта (`.t-num`, `font-variant-numeric: tabular-nums`). Моноширинный шрифт для чисел не используется.
- **Секция отчёта** (`ReportSection`) — это заголовок, необязательное пояснение и контент, без надзаголовков. Primary-кнопка — одна на экран.
- **Согласованность метрик.** Одна величина не может давать два разных ответа ни на одном экране, ни между отчётом и «Итогами» (вопросы — всегда серии `questionTurns`). Окно «обычно на связи» берётся из `derived.availabilityProfile.peakWindow` везде: в KPI, во вкладке «Активность» и в «Итогах».
- **Телефон.** Отчёт — одна длинная страница из трёх частей (`ReportPart`, якоря `#part-<id>`): «Вы двое / Время / О чём», в группе «Люди / Общение / Время». `ReportNav` — закреплённая якорная навигация на всю ширину телефона, подсвечивает раздел при прокрутке. На отчёте, `/new` и в аккаунте — стрелка «назад» (`UiPageBar back`). В шапке отчёта только «Итоги» и «Обновить». Кнопки удаления на странице отчёта нет: удаляют из меню строки чата на «Новом анализе» и в аккаунте.
- **«Итоги».** `ReportStory.vue` собирает слайды, `StorySlide.vue` их рисует. Размеры задаются в `cqmin`. Контейнером служит корень `.story-slide`, а у самого корня не должно быть свойств в cq-единицах: html2canvas посчитает их от своего вьюпорта, и экспорт поедет. Экспорт рендерит отдельную копию с `still` (без анимации).
- **e2e-селекторы.** Тесты опираются на `.chat-row`, кнопки «Анализ» и «Открыть отчёт», роли `tab` у `ReportNav` (клик прокручивает к `#part-…`), `.stories__segment` и `.story-slide__title`. Меняешь что-то из этого — правь тесты.
- **Аналитика.** Логика живёт в `packages/shared` в виде чистых функций и покрывается тестами. Производные метрики считаются при чтении (`deriveReportMetrics`), поэтому их можно улучшать без повторного анализа. Активность групп («писали в последний месяц», роли) считается от последнего сообщения в чате, а не от текущей даты.

## Git

- Работаем в `main`, владелец просит коммитить и пушить туда. Сообщения коммитов — на английском, в стиле истории репозитория (короткий заголовок о том, что стало лучше для пользователя).
- Папка проекта у владельца: `L:\tganalizer` (Windows). При работе через связь с компьютером git должен иметь право удалять lock-файлы. Без этого `commit` и `checkout` ломают репозиторий.
- ⚠️ В `origin` вписан GitHub-токен прямо в URL. Владельцу рекомендовано отозвать токен и подключить GitHub к Claude. Токен нигде не выводи и не копируй.

## Как сдавать работу

1. Если задача большая, сначала аудит и план, потом правки.
2. Прогнать все проверки и сделать скриншоты «после».
3. Обновить `docs/ROADMAP.md`, а при изменении архитектуры — `docs/ARCHITECTURE.md`.
4. Коммит и пуш, затем короткий отчёт владельцу: что изменилось для пользователя и что осталось.
