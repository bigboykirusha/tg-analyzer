## Продукт

«Зеркало ваших переписок»: человек входит через Telegram, выбирает личный чат или группу и получает понятный отчёт. В отчёте баланс переписки, скорость ответов, ритм по часам и дням, частые слова и эмодзи, разговоры и динамика. Для групп добавляются роли участников, связи и общий словарь. «Итоги» — сторис в стиле Spotify Wrapped, которые можно сохранить картинкой 1080×1920 или отправить.

Главное обещание — приватность: тексты сообщений не сохраняются, в базе лежит только агрегированный отчёт, а удалить всё можно в один клик.

Главный объект — отчёт по чату. Главная страница отвечает на два вопроса: «что я уже узнал» (карточки отчётов) и «что ещё можно разобрать» (список чатов).

Основной язык интерфейса — русский, английский тоже поддерживается. Владелец пишет по-русски, отвечать ему по-русски.

## Стек и структура

pnpm-монорепо, Node 22.

```text
apps/web         Nuxt 4 (Vue 3, Pinia), ECharts, html2canvas; свой UI-кит без фреймворка
apps/api         Fastify 5 (src/index.ts), BullMQ worker (src/worker.ts), Drizzle + PostgreSQL, Redis, gramjs
packages/shared  контракт API (zod), типы и вся аналитика отчёта — чистые функции с тестами
docs/            ARCHITECTURE, DEPLOY, ENVIRONMENT, SECURITY, RUNBOOK, UX-REVIEW, ROADMAP
```

Деплой: Railway, три сервиса из одного репозитория (`railway.json` + `scripts/service.mjs`, процесс выбирается через `START_SERVICE=api|worker|web`). Подробности в `docs/DEPLOY.md`.

## Запуск в демо-режиме (без Telegram)

```bash
pnpm install
cp .env.example .env     # заполнить SESSION_ENCRYPTION_KEY, JWT_SECRET, JWT_REFRESH_SECRET (openssl rand -hex 32)
docker compose up -d postgres redis
pnpm db:migrate
pnpm dev                 # web :3000, API :3001, worker
```

- `TELEGRAM_MODE=fake` включает встроенный демо-аккаунт. Входить можно с любым номером, код `12345`. Номер, оканчивающийся на `9`, дополнительно спросит пароль `secret`.
- Демо-чаты: Мила (1001, 4800 сообщений), Мама, Артём, Sofia, Дима (работа), Катя (1006), Олег, Анна. Группы: Продуктовая команда (-1002001), Семья, Бег по утрам, Weekend plans (-1002004). Каналы и бот в список не попадают.
- Демо-чаты заканчиваются сегодняшним днём (кроме тех, у кого задан `quietDays`).
- Пустые значения вида `KEY=` в `.env` считаются незаданными (так сделано в `apps/api/src/config.ts`).
- ⚠️ В `.env` владельца `DATABASE_URL` и `REDIS_URL` смотрят в облачные Neon и Upstash. Для локального демо передавай их явно, переменные окружения важнее `.env`: `DATABASE_URL=postgresql://postgres:password@127.0.0.1:5432/tganalyzer REDIS_URL=redis://127.0.0.1:6379 TELEGRAM_MODE=fake`. Никогда не запускай fake-worker и `db:migrate` против облака.

**Без Docker** (облачная сессия Claude): Postgres 16 и redis-server стоят в системе. Нужно сделать `initdb` во временный каталог, создать базы `tganalyzer` и `tganalyzer_test`, запустить redis на портах 6379 и 56379, затем запустить api, worker и web через `pnpm --filter … dev`. Для e2e добавь `AUTH_RATE_LIMIT_MAX=1000` в `.env`: иначе частые входы упрутся в лимит.

## Проверки (всё должно быть зелёным перед сдачей)

```bash
pnpm lint && pnpm format:check && pnpm check     # ESLint, Prettier, TypeScript (web — nuxt typecheck)
pnpm test:unit                                   # аналитика в packages/shared
pnpm services:test && pnpm test                  # + интеграционные тесты API (Postgres :55432, Redis :56379)
pnpm test:e2e                                    # Playwright, mobile + desktop; нужен поднятый стек в fake-режиме
```

- Без Docker интеграционные тесты запускаются с `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- e2e против уже запущенного стека: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` (из `apps/web`).
- Визуальная проверка обязательна: скриншоты Playwright на 1440×900 и 390×844 (`isMobile`), светлая и тёмная тема. Горизонтального скролла на ширине 360–430 px быть не должно.

## Правила кода и дизайна

- **Тексты** только через i18n: `apps/web/app/i18n/en.ts` — источник ключей, `ru.ts` обязан покрывать все ключи (это проверяет TypeScript). Множественное число — суффиксы `.one/.few/.many/.other` и функция `tc()`. После удаления текста удаляй и неиспользуемые ключи.
- **Цвета и размеры** только через токены `apps/web/app/assets/styles/tokens.css`. Никакого `color-mix()` и захардкоженных цветов в компонентах: новый оттенок — это новый токен со значением для каждой темы. Колонка страницы задаётся через `--page-max` и `--page-gutter`, шапка и все страницы стоят в одной колонке. Радиусы — `--radius-mark/xs/sm/md/lg/xl/full` = 3/6/10/14/22/28/pill (что где — docs/design-system.md §5), отступы — только `--space-*` (сетка 4), длительности — `--duration-fast/normal/slow/sheet/chart/spin`, трекинг — `--tracking-*`, крутилка — только `.spinner`. В графиках ink — только «вы», лайм — собеседник, весь чат — `--chart-neutral(-strong)`, интенсивность — `--heat-*`. Тёмная тема описана один раз в `:root[data-theme='dark']`: системную тему до первой отрисовки ставит скрипт в `<head>` (`nuxt.config.ts`), копию под `prefers-color-scheme` не заводим. Hover-стили — только в `@media (hover: hover) and (pointer: fine)`.
- **Каркас страницы.** Публичные страницы (лендинг, вход, FAQ, пример, 404/ошибки) живут в `layouts/default.vue`: `SiteHeader` + страница + `SiteFooter` (уведомление о Telegram API, документы, язык, тема). Кабинет — `layouts/workspace.vue`: `AppHeader` — одна шапка на всю ширину и на ПК, и на телефоне (логотип, заголовок экрана, действия, профиль; на ПК логотип стоит над боковой панелью, ширина `--sidebar-width`), под ней на ПК `AppSidebar` без своего логотипа и профиля (на телефоне «Новый анализ» — кнопка в шапке главной, плавающих панелей нет). Логотип везде — `BrandLink`. Своих шапок и логотипов на страницах не заводим.
- **Страница внутри каркаса:** `UiPageContainer` → `div.page` (ритм `--page-gap`) → секции `UiPageSection` (h2 стилем `.t-h3`). Заголовок экрана в кабинете и в примере отчёта — `UiPageBar`: он телепортируется в общий хедер (`#header-page` в `AppHeader` / `SiteHeader`) и несёт единственный h1, короткую строку и действия. Своих шапок на страницах кабинета не делаем. FAQ оставляет `UiPageHeader` в странице. Страницы «Условия» нет. Отступы сверху и снизу задают layout-ы через `--page-top` / `--page-bottom`. `size="narrow"` ограничивает ширину контента, но он остаётся выровнен по левому краю под логотипом. Вход и статус-страницы — исключение: одна карточка по центру.
- **Типографика — одна шкала из десяти ролей** (docs/design-system.md §3): `--text-display` (только лендинг), `--text-figure` (одно главное число), `--text-h1/h2/h3`, `--text-title`, `--text-body`, `--text-ui` (контролы), `--text-small`, `--text-caption`. Начертания только 400 и 500. Классы: `.t-h1` заголовок страницы, `.t-h2` заголовок карточки, диалога или статуса, `.t-h3` секция страницы, `.t-title` плитка или строка, `.t-lede` лид. Свои размеры в компонентах не задаём. Живой UI-кит — `/kit` в dev-режиме (в production его нет): новый компонент или вариант добавляй туда. Моноширинного шрифта и надзаголовков-«киккеров» в системе нет. Ссылка в тексте — `.link`.
- **Компоненты.** UI-кит лежит в `components/ui` и вызывается с префиксом `Ui…` (`UiButton`, `UiSegmentedControl`). Остальные компоненты вызываются по имени файла. Иконки импортируются только из `lib/icons.ts` (Lucide).
- **Числа** выводятся табличными цифрами основного шрифта. Правило стоит в `base.css` на `#__nuxt *` и `#teleports *`: шорткат `font:` в компонентах сбрасывает `font-variant-numeric`, а id-селектор его перебивает. Моноширинный шрифт для чисел не используется. Число и единица не разрываются (неразрывный пробел, окна времени — `.nowrap` или U+2060 вокруг тире).
- **Карточка отчёта** (`ReportSection`) — заголовок-вопрос, необязательное пояснение, ответ одной фразой (`answer`), картинка. Строки сторон внизу («Вы · N Имя · M») нет: стороны подписаны в самой картинке. Шкала карточки одна (docs/report-spec.md §3.1): вопрос `--text-title`, ответ и значения `--text-h2`, одно главное число `--text-figure` (72 → 56 на телефоне), подписи `--text-small`, оси и легенды `--text-caption`; эмодзи — `--emoji-size`; иконки — классы `icon-md`/`icon-lg` (`--icon-size`), своих width/height не задаём. Отступы внутри карточки 4/8/16. Primary-кнопка — одна на экран.
- **Плитки.** Белые карточки сливаются в одно поле, поэтому часть блоков окрашена (идея владельца). Тон задаётся только пропом `tone` у `ReportSection` или классом `.tile--ink | .tile--lime | .tile--grey`, своих фонов нет. Смысл тонов: **ink** — главное и записи (итог экрана, хроника, игры), **lime** — ответ и собеседник (кто пишет больше, реакции, ключевые моменты, «ещё не разобран»), **grey** — тихая справка (состав, утро и вечер), **белая** — всё остальное. Правила: две плитки одного тона не соседствуют (ни в ряду, ни одна под другой); окрашено не больше трети карточек; внутри плитки только её токены (`--on-*`, `--tile-grey`), другие плитки внутри плиток не кладём. В тёмной теме ink — приподнятая тёмная поверхность (не белая плита), lime остаётся лаймом и единственной яркой плиткой, grey — тихая ступень над `--surface`. Новый тон — новый токен в обеих темах и строка здесь. Карточки части отчёта (`ReportPart columns`) раскладывает `useMasonry`: две колонки на ≥901 px, каждая карточка на своей высоте и встаёт туда, где колонка освободилась раньше; на телефоне обычная колонка. Все страницы кабинета стоят в одной колонке `--page-max`, у аккаунта две группы настроек рядом. Полоски-пропорции — только `--bar-height` (6 px), радиус pill. Сравнение двух сторон — один компонент `ReportLine` («значение ━━━ ━━ значение»), строки карточки — глобальные `.report-rows*`, аватар стороны — `ReportSideAvatar` («Я» ink, у собеседника первая буква).
- **Сравнения «вы против собеседника»** считает только `useVersus`. Порядок «Вы двое» (`ReportDuel`, файлы `components/report/duel/*`): «Кто отвечает быстрее» (ответ и `ReportLine`; при паритете вместо полоски два времени с аватарами), grey «Ваши привычки» (кто начинает, кто смеётся и — если у голосовых нет длительности — кто чаще шлёт голосовые), квадраты вопросов (не больше ~100), стикеры строками по сторонам (по 4, аватар слева), lime-пьедесталы реакций, одна карточка голоса (ответ, `ReportLine` длительностей, факты «Вместе» и «Самое длинное»), «Доброе утро и спокойной ночи», «Кто открывает и закрывает день». Служебной строки «Нет в этом чате…» нет. `ReportLine` не рисует отрезок для нуля и ставит «—». При паритете у каждой карточки своя фраза (`report.fmt.*Even`, «Идеальный баланс», «Отвечаете синхронно»…). «О чём»: «Слово переписки» (слово лаймом в `--text-figure-lg`, сколько раз, места 2–4 под линией), «Ваш словарь» (`splitVocabulary`: строки «только вы / только собеседник» и «Общие»), «Любимые эмодзи» строками с `ReportLine`. Верх отчёта — `ReportHero`: ink с числом, пульсом (легенда точками в строке заголовка, не больше 40 столбиков — неделя, две или месяц) и главами переписки под ним (`computeChapters` в shared, `ReportChapters`: до пяти периодов по объёму, у ровного или короткого чата глав нет — тогда ось месяцев); отдельной карточки «Объём переписки» нет. Под hero после повторного анализа — белая полоса «С прошлого анализа» (`ReportSince`: новые сообщения, ваш ответ, кто начинает; без новых сообщений её нет). «Время»: «Ваше время», «Ваши рекорды», ink «Круглые сообщения» (`ReportMilestones`: вехи из `milestones` и прогноз следующей `forecastMilestone`), «Активность по дням» — календарь месяцами (`ActivityHeatmap`, на телефоне 3 в ряд и последние 6) с ответом «Писали друг другу N из M дней». рядом лаймовая «Кто пишет больше» (ответ, «52 / 48», `ReportLine`). «Чем выделяется этот чат» убран. Верх главной — «Чарт месяца» (`MonthSummary`: пять одинаковых строк со стрелками против места по размеру за всё время) и тонкая лаймовая полоса «Ещё не разобран» со второстепенной кнопкой. В группе лидеры по привычкам — плитки `GroupAwards`.
- **Согласованность метрик.** Одна величина не может давать два разных ответа ни на одном экране, ни между отчётом и «Итогами» (вопросы — всегда серии `questionTurns`). Окно «обычно на связи» берётся из `derived.availabilityProfile.peakWindow` везде: в KPI, во вкладке «Активность» и в «Итогах».
- **Телефон.** Отчёт — одна длинная страница из трёх частей (`ReportPart`, якоря `#part-<id>`): «Вы двое / Время / О чём», в группе «Люди / Общение / Время». `ReportNav` — закреплённая якорная навигация на всю ширину телефона, подсвечивает раздел при прокрутке. На отчёте, `/new` и в аккаунте — стрелка «назад» (`UiPageBar back`). В шапке отчёта: назад, аватар, имя и одна кнопка «Поделиться» (`ShareDialog`: превью «Итогов», «Смотреть итоги», «Сохранить картинками», «Отправить» там, где браузер умеет делиться файлами; под линией «По ссылке» — «Ссылка на отчёт» и «Угадайка» вторым шагом той же модалки, публичная страница `/s/:token`; групповые отчёты по ссылке не отдаём). «Обновить» — в меню строки чата. Кнопки удаления на странице отчёта нет: удаляют из меню строки чата на «Новом анализе» и в аккаунте.
- **«Итоги».** `ReportStory.vue` собирает слайды, `StorySlide.vue` их рисует. Личный чат — четыре плотных слайда (обложка, «Вы двое», «Ваше время», «О чём»), не больше трёх рядов плиток на слайд: всё должно влезать в 9:16 между безопасными зонами. Сравнение сторон — блок `split`. Размеры задаются в `cqmin`. Контейнером служит корень `.story-slide`, а у самого корня не должно быть свойств в cq-единицах: html2canvas посчитает их от своего вьюпорта, и экспорт поедет. Экспорт рендерит отдельную копию с `still` (без анимации).
- **e2e-селекторы.** Тесты опираются на `.chat-row`, `button.month__row` («+ Разобрать чат» в «Чарте месяца»), кнопки «Анализ», «Открыть отчёт», «Поделиться» в шапке отчёта и «Смотреть итоги» в его окне, роли `tab` у `ReportNav` (клик прокручивает к `#part-…`), `.stories__segment` и `.story-slide__title`. Меняешь что-то из этого — правь тесты.
- **Аналитика.** Логика живёт в `packages/shared` в виде чистых функций и покрывается тестами. Производные метрики считаются при чтении (`deriveReportMetrics`), поэтому их можно улучшать без повторного анализа. Активность групп («писали в последний месяц», роли) считается от последнего сообщения в чате, а не от текущей даты.

## Git

- Работаем в `main`, владелец просит коммитить и пушить туда. Сообщения коммитов — на английском, в стиле истории репозитория (короткий заголовок о том, что стало лучше для пользователя).
- Папка проекта у владельца: `L:\tganalizer` (Windows). При работе через связь с компьютером git должен иметь право удалять lock-файлы. Без этого `commit` и `checkout` ломают репозиторий.
- ⚠️ В `origin` вписан GitHub-токен прямо в URL. Владельцу рекомендовано отозвать токен и подключить GitHub к Claude. Токен нигде не выводи и не копируй.

## Как сдавать работу

1. Если задача большая, сначала аудит и план, потом правки.
2. Прогнать все проверки и сделать скриншоты «после».
3. Обновить `docs/ROADMAP.md`, а при изменении архитектуры — `docs/ARCHITECTURE.md`.
4. Коммит и пуш, затем короткий отчёт владельцу: что изменилось для пользователя и что осталось.
